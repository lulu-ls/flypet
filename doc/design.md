# FlyPet 设计文档

> 桌面飞虫宠物：从指针处生成一只可更换皮肤的飞虫，随机停在屏幕上，鼠标靠近则飞走。目标平台：macOS + Windows，体积尽量小。

## 1. 结论

**可以实现，且适合做成跨平台小工具。**

三个核心能力在 macOS / Windows 上都有成熟系统 API：

| 能力 | macOS | Windows | 是否需要额外权限 |
|------|--------|---------|------------------|
| 全局指针坐标 | `NSEvent.mouseLocation` | `GetCursorPos` | 否 |
| 无边框透明置顶窗口 | `NSWindow` + `ignoresMouseEvents` | `WS_EX_LAYERED` + `WS_EX_TRANSPARENT` | 否 |
| 窗口跟随飞虫移动 | 每帧 `set_position` | 同左 | 否 |

网页本身**不能**独立完成这个产品：浏览器 / WebView 只能在窗口内部收到鼠标事件。飞虫要在整块桌面上停、躲、飞，必须由原生层轮询全局指针，再驱动一个很小的透明窗口。

不需要辅助功能、屏幕录制或注入其他进程。这是一个纯「叠加层 + 指针坐标」应用。

---

## 2. 产品定义

### 2.1 要做的事

1. **指针处生成**：启动时在当前光标附近出现一只飞虫，随后飞到屏幕某处停下。
2. **随机停留**：停在桌面随机位置，偶尔轻微振翅 / 挪动，像真的停着。
3. **靠近飞走**：光标进入警戒半径后，沿远离光标的方向飞到新落点。
4. **可换皮肤**：同一套行为，资源换成蝴蝶、蜜蜂、苍蝇等。
5. **不打扰工作**：默认点击穿透，用户仍能操作下面的窗口。

### 2.2 明确不做（v1）

- 不读取其他窗口内容，不「停在某个 App 标题栏上」做像素级吸附。
- 不模拟真实物理碰撞桌面图标。
- 不跟随光标当装饰指针（那是另一种产品）。
- 不默认拦截点击。打苍蝇、拖动等交互放到 v2。

### 2.3 成功标准

- 飞虫能在主屏（v1）任意位置停留和飞走。
- 光标靠近时明显躲开，停下后不会贴着光标抖。
- 使用电脑时几乎无感：不抢焦点、不挡点击、CPU 接近空闲。
- macOS / Windows 同一套逻辑，平台差异关在原生适配层。
- 安装包明显小于 Electron 方案（目标见第 7 节）。

## 3. 关键约束

### 3.1 为什么不能用普通网页窗口

先前若用「400×400 透明 Web 窗口 + `mousemove`」会失败，原因：

1. 飞虫活动范围被锁在窗口矩形内，不是整块屏幕。
2. 光标在窗口外时，前端收不到鼠标位置。
3. 窗口若不点击穿透，会挡住所有桌面操作；若整窗穿透，前端更收不到鼠标。
4. 全屏透明 WebView 覆盖桌面，在多屏、HiDPI、全屏游戏上更重、更易闪。

正确模型是：**原生负责「世界坐标 + 窗口位置」，前端只负责「画这只虫」。**

### 3.2 窗口策略对比

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| A. 全屏透明覆盖 | 一块铺满屏幕的 WebView，在画布上画虫 | 动画坐标系简单 | 大面积透明合成、多屏难、易误挡点击 | 不采用 |
| B. 小窗跟随 | 80–128px 无边框透明窗，每帧移到虫的位置 | 合成面积小、省电、像桌宠 | 要处理 DPI / 多屏坐标 | **v1 采用** |
| C. 纯原生绘制 | `winit` + 贴图，无 WebView | 体积最小 | 换皮肤动画成本高 | 体积极端时的备选 |

v1 采用 **B**：窗口约等于虫子大小，窗口中心 ≈ 虫子世界坐标。

## 4. 技术选型

### 4.1 框架对比

| 方案 | 典型体积 | Mac/Win | 全局鼠标 | 透明置顶 | 换皮肤 | 评价 |
|------|----------|---------|----------|----------|--------|------|
| Electron | 150–200MB | 好 | 要 native addon | 可以 | 很容易 | 体积不合格 |
| Python + Qt/PyInstaller | 40–80MB | 一般 | 可以 | 可以 | 一般 | 体积和启动都不理想 |
| 纯 Rust（winit + 贴图） | 2–5MB | 好 | 最好 | 要自己处理 | 要手写动画 | 最小，但皮肤系统慢 |
| **Tauri 2 + Rust 逻辑** | **约 4–10MB** | **好** | **Rust crate / FFI** | **官方支持** | **HTML/CSS/APNG 很容易** | **推荐** |

### 4.2 推荐栈

```
┌─────────────────────────────────────────────┐
│  前端（系统 WebView，无 Vue/React）          │
│  只渲染当前皮肤：静止 / 振翅 / 飞行          │
└──────────────────────▲──────────────────────┘
                       │ 状态：skin, pose, facing
┌──────────────────────┴──────────────────────┐
│  Rust 核心                                   │
│  指针采样 → 状态机 → 新世界坐标 → 移动窗口   │
│  托盘、退出、换皮肤、配置                    │
└─────────────────────────────────────────────┘
```

- **壳**：Tauri 2（用系统 WebView，不内嵌 Chromium）。
- **逻辑**：Rust。指针、屏幕、窗口移动都在这一层，保证 30–60Hz 稳定。
- **表现**：原生 HTML + CSS（或一张 APNG）。不引入 Vue / React，避免为「一只虫子」拖框架。
- **指针库**：`mouse_position` 或直接调平台 API。macOS 用 `NSEvent.mouseLocation` 即可，**不必**申请辅助功能权限。
- **托盘**：Tauri tray。退出、暂停、换皮肤都走托盘，避免虫子抢点击。

不选 Electron：体积差两个数量级。  
不选 Vue：这个 UI 没有复杂组件树。  
不在 JS 里做物理：JS 拿不到可靠的全局指针。

### 4.3 备选

若后续确认皮肤只是静态 PNG、且希望安装包再小一圈，可把前端换成 `softbuffer` 贴图，逻辑层几乎不用改。设计上把「世界坐标 / 状态机」和「怎么画」分开，就是为了留这条退路。

## 5. 行为设计

### 5.1 状态机

```
          启动
            │
            ▼
     ┌────────────┐  飞到随机落点   ┌────────────┐
     │   Spawn    │ ─────────────► │   Perch    │
     └────────────┘                └─────┬──────┘
                                         │
                    光标进入警戒半径      │ 停留超时
                                         ▼
                                   ┌────────────┐
                                   │    Flee    │
                                   └─────┬──────┘
                                         │ 到达新落点
                                         ▼
                                       Perch
```

| 状态 | 表现 | 退出条件 |
|------|------|----------|
| `Spawn` | 从当前光标附近出现，立刻飞向第一落点 | 到达落点 |
| `Perch` | 停住，低频率振翅、偶尔平移 2–8px | 光标进入 `fleeRadius`，或停留超过 `idleTimeout` |
| `Flee` | 沿远离光标方向飞到新落点，速度先快后慢 | 距离目标 < 4px |

> **玩法扩展原则**：后续玩法（投喂 `Seek/Eat`、说话等，见 [`gameplay.md`](gameplay.md)）以**注册式行为**接入——每个行为实现 `on_enter / update / on_exit`，主循环只调 `current.update(ctx, dt)`，加行为不加分支。

### 5.2 参数（可配置，单位：物理像素）

| 参数 | 建议默认 | 说明 |
|------|----------|------|
| `fleeRadius` | 96 | 进入则起飞。太大太敏感，太小像没反应 |
| `safeRadius` | 240 | 新落点必须离光标至少这么远 |
| `perSpeed` | 420 px/s | 飞行峰值速度 |
| `fleeBoost` | 1.4 | 刚起飞的加速倍数，避免被光标追上 |
| `idleTimeout` | 8–20s 随机 | 没人碰也会换地方 |
| `fidgetChance` | 很低 | 停留时轻微挪动，增加活感 |
| `windowSize` | 96×96 | 窗口边长，略大于皮肤 |

### 5.3 飞走方向

不要随机乱飞，也不要直线远离后卡在屏幕边缘。

1. 取向量 `insect - cursor`，归一化。
2. 加一个小随机偏角（±30°），避免每次同一条路。
3. 在该方向上取距离 `safeRadius ~ 屏幕短边的 40%` 的候选点。
4. 若出屏或离光标太近，绕屏幕中心旋转候选方向再试，最多若干次。
5. 仍失败则退回「当前屏内随机点，且满足 `safeRadius`」。

飞行用 **ease-out**：起步快、落地前减速。朝向按速度向量左右翻转皮肤。

### 5.4 「指针位置生成」的精确含义

v1 只生成 **一只**：

- 启动瞬间读取全局光标。
- 虫子出现在光标附近（偏移 12–24px，避免正挡住指针）。
- 随即进入 `Flee`/`Spawn`，飞向第一落点。

以后若要「单击托盘 → 再放一只」，状态机按实例复制即可，窗口策略仍是「一虫一窗」或「一窗多虫」。v1 先做一虫一窗。

## 6. 原生层设计

### 6.1 主循环

独立线程，不要绑在 WebView 帧上：

```
loop every 16ms (可降到 33ms):
  cursor = global_mouse_position()
  screen = current_display_bounds(insect.pos)
  insect.update(cursor, screen, dt)
  window.set_position(insect.pos - window_size/2)
  if pose_changed:
      emit("pose", { skin, pose, facing })
  sleep
```

停留且光标很远时，可降到 10Hz，降低空闲 CPU。

### 6.2 坐标

全程使用 **桌面全局物理像素**（各屏拼起来的虚拟桌面）。

注意：

- macOS：原点在**主屏左下**，y 向上；Tauri/Web 原点在左上。转换必须集中在一个函数。
- Windows：原点左上，但 Per-Monitor DPI 下「逻辑像素 / 物理像素」会混。窗口移动统一用物理像素，皮肤 CSS 用 `px` 时按 DPI 缩放窗口。
- v1 先保证 **主屏**；多屏在拿到 `available_monitors()` 后把落点限制在「虫子当前所在屏」，避免飞到缝里或负坐标。

### 6.3 窗口属性

必须同时具备：

- 无边框、透明、始终置顶
- 不出现在任务栏 / Dock（工具窗口或 `skipTaskbar`）
- 不抢焦点（macOS `NSWindowStyleMaskNonactivatingPanel` 一类）
- **默认点击穿透**（`set_ignore_cursor_events(true)`）
- 阴影关闭，避免一块大方框

### 6.4 点击穿透与「以后打苍蝇」

v1 永远穿透，交互全在托盘。

v2 若要点虫子：

1. 每帧做一次点是否落在虫子不透明像素上（或简单圆形 hit）。
2. 命中则暂时关闭穿透，未命中保持穿透。
3. 这是桌宠常见做法，但会引入「偶发抢点击」风险，所以不进 v1。

### 6.5 托盘

- 显示 / 隐藏
- 暂停（冻在原地）
- 换皮肤：苍蝇 / 蜜蜂 / 蝴蝶
- 投喂（二期玩法入口，见 [`gameplay.md`](gameplay.md)）
- 退出

配置写到应用数据目录的 `settings.json`；宠物档案（亲密度、阶段等）写到同目录 `data.json`（见 [`gameplay.md`](gameplay.md) §2）。

### 6.6 气泡窗口（说话用，二期）

96px 虫子窗口放不下台词气泡，增加第二个窗口：无边框透明置顶穿透、skipTaskbar，约 140×64，跟随虫子右上角并 clamp 在工作区内；显示 3–5s 后淡出。无台词时隐藏。详见 [`gameplay.md`](gameplay.md) §6。

## 7. 前端与皮肤

### 7.1 前端职责

只接收 `{ skin, pose, facing }`：

- `pose = perch | fly | fidget`
- `facing = left | right`

用 CSS 切帧或播 APNG。不要在前端算位置。

### 7.2 皮肤包格式

```
skins/
  fly/
    meta.json
    perch.png
    fly.png          # 或 fly.webp / fly.apng
    eat.png          # 二期：进食帧（frames 允许任意 pose key，缺帧回退 perch）
  bee/
    ...
  butterfly/
    ...
```

> **进化承载**（三期）：每个皮肤下可挂 `stages/{1..4}/` 子目录（卵 → 幼虫 → 成虫 → 华彩），子 meta 继承主 meta 只覆盖差异帧。进化 = 改档案阶段号 + 换资源，不加逻辑分支。定义见 [`gameplay.md`](gameplay.md) §5。

`meta.json` 示例：

```json
{
  "id": "fly",
  "displayName": "苍蝇",
  "size": 64,
  "anchor": [0.5, 0.5],
  "frames": {
    "perch": { "src": "perch.png", "fps": 4 },
    "fly": { "src": "fly.png", "fps": 12 }
  }
}
```

换皮肤 = 换资源，不改状态机。这是「后期可换蝴蝶 / 蜜蜂 / 苍蝇」的真正扩展点。

v1 可用 CSS 画简化矢量虫，不挡开发；正式版再换插画。

## 8. 体积与依赖预算

| 部分 | 预算 |
|------|------|
| Rust 二进制 + 资源 | 2–4MB |
| 系统 WebView | 0（已在 OS 里） |
| 皮肤（3 套 PNG/APNG） | 0.3–1MB |
| **安装包目标** | **macOS app / Windows exe 合计约 5–12MB** |

对比：Electron 同类桌宠通常 >150MB。

依赖原则：

- 前端零框架。
- Rust 只引窗口、托盘、指针、序列化。
- 不做自动更新（v1）。
- 不做日志框架。

## 9. 跨平台清单

### macOS

- 透明面板 + 置顶 + 不激活。
- `NSEvent.mouseLocation` 无辅助功能权限。
- 全屏游戏 / 另一块 Space：置顶窗口可能不可见，可接受。
- 刘海屏 / 菜单栏：落点避开菜单栏高度约 24–32px。
- 签名公证是分发问题，不是功能问题。

### Windows

- WebView2 是系统组件；极老的机器可能要引导安装，文档里写明。
- `WS_EX_TRANSPARENT` 做点击穿透；分层窗口做透明。
- Per-Monitor v2 DPI：窗口尺寸和坐标都跟当前屏 DPI 走。
- 部分全屏 DirectX 游戏会盖住置顶窗，可接受。
- 任务栏区域不要作为落点。

### 共同

- 开机自启放到 v2。
- 高刷新屏：逻辑仍按时间 `dt` 积分，不要按「每帧位移常数」。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 每帧 `set_position` 在 Windows 上抖动 | 观感差 | 位置用整数像素；速度低时吸附；必要时双缓冲位置 |
| 巨大透明窗吃 GPU | 发热 | 不用全屏覆盖，只用小窗 |
| 误用 CGEvent tap | 触发隐私权限 | 只查询坐标，不截获事件 |
| 飞虫挡住点击 | 没法干活 | v1 强制穿透 |
| 落点总在屏幕外 / 缝里 | 虫子消失 | 落点 clamp 到工作区，多屏先锁当前屏 |
| 光标停在虫子上反复起飞 | 抽搐 | `Flee` 期间忽略警戒，落地后加 300ms 冷却 |
| WebView 透明闪黑 | 启动难看 | 先隐藏窗口，第一帧皮肤就绪再 show |

## 12. 里程碑

1. **Spike（1–2 天）**  
   空透明小窗 + 全局鼠标 + 窗口跟随光标。验证穿透、置顶、DPI。这是整个项目的技术关门条件。

2. **状态机（2–3 天）**  
   Spawn / Perch / Flee 在主屏工作，参数可调。

3. **皮肤（1–2 天）**  
   三套资源切换，托盘菜单。

4. **打磨（2 天）**  
   冷却、工作区 inset、空闲降频、隐藏 Dock/任务栏图标。

5. **打包**  
   macOS `.app` / `.dmg`，Windows `.exe`。量体积，确认不引入 Chromium。

Spike 失败（某平台无法同时做到透明 + 置顶 + 穿透 + 全局鼠标）才需要改方案：退回纯原生贴图窗口。预期不会失败。

## 13. 最终建议

- **做**：Tauri 2 + Rust 状态机 + 96px 透明跟随窗 + 托盘换皮肤。
- **不做**：Electron、全屏 Web 覆盖、在 JS 里跟踪鼠标、v1 点击打虫。
- **体积**：按 10MB 量级设计，而不是 100MB 量级。
- **扩展**：皮肤包与状态机解耦，以后加蝴蝶 / 蜜蜂只加资源；玩法（进化 / 喂食 / 亲密度 / 说话）全部长在「注册式行为 + 事件层」上，见 [`gameplay.md`](gameplay.md)。

可行性没有疑问。真正要盯住的不是「能不能画一只虫」，而是 **全局指针 + 小窗跟随 + 点击穿透** 这三件事同时成立。这三件事在 Mac / Win 上都成立，所以项目成立。
